# TenzorPipe v0.1.9 — independent review and repaired release

I retained the supplied v0.1.8 chunked decoder and repaired two reproduced defects:
chunk payload could exceed its window budget, and an emitter panic could deadlock
scoped worker joins. Indexing now releases mapped pages, planning allocations are
capped, and IDR cut-point validation checks the complete access unit.

The release compiles, passes 26 Rust tests, and passes the independent media,
PyArrow/PyTorch, epoch, boundary, corruption and failure suites. The expanded matrix
contains 600 successful artifact comparisons plus 160 expected-error agreements;
177 runs actually entered chunked mode. No historical result is presented as a new run.

On the same 330-second source, three-run medians are:

| Pipeline | Wall seconds | Median peak RSS MiB |
|---|---:|---:|
| v0.1.9, one video worker | 9.506 | 60.67 |
| v0.1.9, two video workers | 7.312 | 78.85 |
| Supplied v0.1.8, two workers | 7.231 | 81.17 |
| FFmpeg/Python/Arrow baseline | 5.873 | 259.82 |

Use `--video-workers 2` for the measured speed/memory tradeoff. The default remains
one for conservative resource use. The baseline is still faster on the long workload.
Two-worker video-only is 4.726 s; audio-only is
6.585 s. Further video workers are not the next useful
optimization; profile AAC decode/downmix and sinc inner loops next.

Across 330/660/1320 seconds, N2 peak RSS is
78.43 / 79.90 / 83.08 MiB.
The 22-minute old/new tensors are exactly equal. This is measured streaming behavior,
not a claim of formally proven leak freedom.

The ZIP includes the complete repository, current Linux binary, comparison binaries,
short fixtures, tensor images/example, raw evidence, third-party notices and exact
reproduction scripts. Read TEST_REPORT.md, BENCHMARK_REPORT.md, BUILD_STATUS.md,
DEPENDENCY_POLICY.md and CONCURRENCY_REPORT.md for gates and limitations.
Project-specific BUSL terms remain unresolved; no owner terms were invented.
